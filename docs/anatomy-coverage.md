# Anatomy coverage: how it is measured

How complete is this atlas? This document defines the measurement. The numbers
themselves live in [coverage-snapshot.md](coverage-snapshot.md), which is
regenerated by the tooling and is meant to be committed and diffed.

```bash
npm run data:ta2        # TA2 PDF -> data/ta2-terms.json   (only when the PDF changes)
npm run data:coverage   # TA2 x shipped meshes -> matrix, snapshot, history row
```

## The reference

**Terminologia Anatomica, 2nd edition (FIPAT 2019)** — the international standard
inventory of gross anatomy, 7,113 numbered terms. It is the reference because it
is authoritative, complete, stable, and independent of any product we might be
compared to.

It is deliberately *not* another atlas's parts list. The first version of this
tooling compared BodyParts3D against a file that was itself BodyParts3D and
reported 100% coverage. A reference has to come from outside the data.

`scripts/extract-ta2.py` parses the official PDF, which is a six-column table
(Latin | Latin synonym | UK English | US English | English synonym | Other) at
fixed x positions. Rows are rebuilt by binding words to column bands and folding
wrapped lines onto the row above. Two checks guard the parse: TA2 ids must come
out contiguous 1–7113 with no gaps, and UK and US English must agree on ~95% of
rows (they differ only by real spelling variants).

## The denominator

Of 7,113 terms, **5,281 name a structure a 3D atlas could model**. The other 1,832
are excluded:

| Excluded class | Count | Why |
|---|---|---|
| Landmark / feature | 1,159 | A margin, foramen, fossa or crest *on* another structure. No atlas meshes these separately. |
| General anatomy (ch. 1) | 350 | Planes, axes, terms of movement. Nothing to model. |
| Space | 164 | Cavities, recesses, compartments — the absence of tissue. |
| Section heading | 111 | Group headers like "BONES OF UPPER LIMB". |
| Abstract class | 48 | "Long bone", "Sesamoid bone" — a category, not a part. |

Capitalised rows need care: TA2 prints section headers in capitals, but many of
them name one real organ or bone (FEMUR, HEART, DIAPHRAGM). Only rows that read
as a group — "X OF Y", a plural collective, or an explicit grouping noun — are
treated as headings.

## What counts as present

A structure counts as present only when **a GLB node carrying real triangles**
exists for it, in a pack the app actually ships. A catalog row is not coverage,
and neither is a name in a manifest. `scripts/coverage-matrix.mjs` reads the
geometry out of every `public/models/{male,female}/*.glb` and counts triangles
per node before it counts anything as covered.

Two grades of match:

- **exact** — a mesh name normalises to the same key as the TA2 term.
- **partial** — every word of the TA2 term appears in some mesh name, so the
  structure is present but modelled at finer grain. TA2's *Deltoid* against a
  shipped *Acromial part of right deltoid*.

## Matching, and its error bar

Matching is by normalised English name, because no free crosswalk maps TA2 ids to
FMA ids. Normalisation drops laterality and redundant head nouns, folds plurals
and known irregulars, and compares sorted token sets, so TA2's *Sartorius muscle*
matches a shipped `right-sartorius`.

**Measured false-negative rate: about 5%**, by sampling 40 rows from the missing
list and hand-searching the mesh names for each. That moves the headline
percentage by a point or two. It does not change the shape of the gap, and the
per-kind ordering is robust to it.

Re-run that sample after any change to the matcher. If it climbs above ~10% the
matcher is doing more harm than the gap it is measuring.

## Outputs

| File | What it is | Committed |
|---|---|---|
| `data/ta2-terms.json` | The 7,113-term reference | yes |
| `data/coverage-matrix.json` | Full matrix plus per-chapter and per-kind rollups | yes |
| `data/coverage-matrix.csv` | One row per TA2 term, for spreadsheets | yes |
| `docs/coverage-snapshot.md` | Human-readable summary, regenerated each run | yes |
| `data/coverage-history.csv` | One row per *change*, with the mesh sources that produced it | yes |

A run that moves nothing appends nothing, so the history stays a list of the
moments coverage actually changed rather than a log of how often it was checked.

## Raising coverage

The gap is a property of the source meshes, not of this pipeline. Raising
coverage means adding a mesh source — see [mesh-sources.md](mesh-sources.md) for
what has been evaluated, what each one is worth in coverage points, and the
share-alike obligations that come with them.

That is how coverage went from 18.1% to 35.6%: merging Z-Anatomy added 924
structures, and `data/coverage-history.csv` holds both measurements. Both
adopted sources are now fully ingested, so the next step up needs a third one.
